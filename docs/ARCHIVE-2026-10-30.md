## 1. 问题与根因查证

**现象**：Office 2019 永久版旁加载后任务窗格白屏（同 manifest 在 2024/365 正常）。

**根因**（已联网核实）：

| 事实 | 说明 |
| --- | --- |
| 任务窗格 WebView 锁死 IE11（Trident） | Office 2019 永久版的 webview 类型固定为 IE11，微软官方**不提供 WebView2 回移植**（office-js 团队 2022 年在 GitHub 明确表态） |
| `<script type="module">` 被 IE11 忽略 | Vite 产出的现代 JS 包根本不会加载 → 白屏 |
| Vue3 无法在 IE11 运行 | Vue3 依赖 `Proxy`，IE11 无法 polyfill（Element Plus 同理） |
| Office.js API 上限（volume-licensed） | WordApi **1.3** / ExcelApi **1.7** / PowerPointApi **1.1** |

**方案对比**：A) 放弃 2019；B) 完整重写 IE11 兼容前端（Vue2 + Element UI + plugin-legacy 产 ES5）；C) 降级整个项目到 Vue2；D) 静态构建两套。**选 B**：双前端共存，现代版零改动，2019 走独立兼容包。

## 2. 双前端架构

```
dist/
├─ index.html + assets/index-*          ← 现代版（Vue3 + Element Plus，WebView2/Chrome）
└─ taskpane-legacy.html
   ├─ assets/legacy-taskpaneLegacy-<hash>.js        ← 现代包（IE11 不下载）
   ├─ assets/legacy-taskpaneLegacy-legacy-<hash>.js ← ES5 包（IE11 执行，acorn 校验通过）
   └─ assets/legacy-polyfills-legacy-<hash>.js      ← core-js + regenerator

server/index.js 按 UA 分流：/Trident\/|MSIE / → taskpane-legacy.html，否则 index.html
manifest.xml 无需改动（同一 URL，服务端自适应）
```

- **现代版源码零改动**（仅 index.html 加 `nomodule` IE11 兜底提示）
- **兼容版全套源码**：`src-legacy/`（独立 `package.json`：vue@2.7.16 + element-ui@2.15.14）
  - `main.js / store.js（Vue.observable）/ api.js / utils.js / styles.css / App.vue`
  - `components/`：ChatView、MessageBubble、ChatInput、SettingsView、HistoryView（选项式 API 重写）
  - `office/index.js`：执行器注册中心复刻；word/excel/ppt 执行器直接复用现代版模块
- **复用切断依赖链**：`stripDataUrl` 从 `src/office/index.js` 抽到 `src/office/dataurl.js`（原文件连带 import Vue3 版 store，IE11 包无法引入）

## 3. 关键决策记录

| 决策 | 理由 |
| --- | --- |
| `src-legacy/` 独立目录 + 独立 node_modules，vite legacy 构建 `root` 指向它 | `@vitejs/plugin-vue2` 的 `resolveCompiler(root)` 从 vite root 解析 `vue/compiler-sfc`；root=项目根会错拿 vue3 编译器。root=src-legacy 后插件与应用代码都解析到 vue2，与根 vue3 完全隔离 |
| IE11 版剔除 `*_run_code` 工具（word 32→31、ppt 31→30） | run_code 依赖 AsyncFunction（async/await 语言特性），IE11 无法执行。协议：客户端 `/api/chat` 带 `caps:{legacy:true}` → 服务端 `toolsForHost(appType, excludeToolNames)` 过滤绑定 |
| SSE 用 XHR `onprogress` 增量解析 `responseText` | IE11 无 fetch / EventSource / TextDecoder / AbortController；`sseStream` 返回 `{promise, abort}` 对齐现代版接口，`abort()` 走 `xhr.abort()` |
| 模板避免 `?.`/`??`，布局不用 flex gap，滚动容器 `flex:1 + height:0` | IE11 不支持可选链/空值合并/gap；flex 子项 min-height 失效用 height:0 绕开 |
| 中文输入法：`compositionstart/end` 自跟踪 + `keyCode 229` 过滤 | IE11 无 `isComposing` 属性，直接监听 Enter 会在组词期间误发送 |
| ES5 校验用 acorn（ecmaVersion:5）真解析，不用正则扫描 | 正则在压缩单行文件上误报率极高（命中全在字符串/正则/注释里：Element UI 模板表达式、linkify-it 字符类、core-js 错误消息等）；解析器零误报 |
| `entry` 命名 `taskpaneLegacy`（不带 `-legacy-` 中缀） | plugin-legacy 给 babel 产物追加 `-legacy-` 中缀，入口名再带会与 module/legacy 包混淆 |
| legacy 构建 `emptyOutDir:false` + 构建前 `clean-legacy.mjs` | 与主构建产物共存 dist/；先清旧 legacy 产物防 hash 累积 |

## 4. 构建与脚本

```bash
npm run build          # 主构建 + legacy 构建（clean-legacy → vite legacy → check-es5）
npm run build:modern   # 仅主构建
npm run build:legacy   # 仅 legacy 构建 + ES5 校验
npm run check-es5      # acorn ecmaVersion:5 解析 dist/assets/legacy-*legacy-*.js
```

依赖：根 devDeps 新增 `@vitejs/plugin-vue2`、`@vitejs/plugin-legacy`、`terser`、`acorn`；
根 dependencies **不**含 vue2/element-ui（避免进安装包）；`src-legacy/package.json` 自持。

服务端改动（3 处）：
- `server/agent.js`：`toolsForHost(appType, excludeNames)`；`runAgentTurn` 解构 `excludeToolNames`
- `server/index.js`：`/taskpane.html` UA 分流；`caps.legacy` → `excludeToolNames`（剔除 `*_run_code`）

## 5. 踩坑记录

| 坑 | 处理 |
| --- | --- |
| 用户手动 `npm install` 中断（ENOTEMPTY）+ 后续 cnpm 重新整理，`better-sqlite3` 原生二进制丢失（`bindings.js` 报找不到 `.node`） | `prebuild-install --download` 走 npmmirror 二进制镜像拉回：`https://registry.npmmirror.com/-/binary/better-sqlite3/v{version}/{name}-v{version}-{runtime}-v{abi}-{platform}-{arch}.tar.gz`（GitHub release 直连会超时；cnpm 用户装依赖时自动走镜像，npm 用户超时时手动用上述命令） |
| cnpm 9.4 对 `npm:` 别名协议可用（`vue2@npm:vue@2.7.16` 装包成功），但最终没用别名方案 | 改为 src-legacy 独立依赖目录后根目录别名冗余，已从根 package.json 移除 |
| `@vitejs/plugin-vue2` peer 不内嵌，config 加载期（Node 层）解析编译器，vite alias 管不到 | 唯一正解是让 vite `root` 指向含 vue2 的目录（源码 `root: config.root` → `resolveCompiler(options.root)`） |
| check-es5 首版正则扫描 33+ 处"疑似 ES6" | 全部为字符串/正则/注释假阳性（上下文打印验证），换 acorn 解析后一次通过 |
| PS5.1 `stderr` 会被当 error 展示（cnpm/prebuild-install 的 info 输出） | 输出重定向 `2>&1 \| Out-String` 或忽略退出码 |

## 7. Office 2019 已知限制（写入 README/安装向导）

- `*_run_code` 三个工具不可用（IE11 语言特性限制），服务端自动隐藏，其余 81 个工具协议不变
- PPT 工具集要求 PowerPointApi 1.8+，2019 上限 1.1 → PPT 工具在 2019 基本不可用
- Word/Excel 基础读写可用（Word API 上限 1.3、Excel 上限 1.7，高于工具所需）
- 兼容版界面与新版略有差异、无 HMR；体验完整建议 2021/2024/365（WebView2）
