## 1. 项目概览

面向 **Office 2021/2024 / Microsoft 365（Word · Excel · PowerPoint）** 的任务窗格加载项：
内嵌 **AI Agent 面板（LangGraph.js）**，将 Office 文档能力封装为 **83 个工具** 开放给大模型，
用户以自然语言直接读写当前打开的文档；支持多会话（SQLite 持久化）、多模型（OpenAI 兼容）、
附件读取、思考过程展示与持久化、上下文额度显示，并可打包为 **Windows 安装程序**（Win10+，免环境）。

| 组件 | 技术栈 |
| --- | --- |
| 前端（任务窗格） | Vue3 + Element Plus + Vite，markdown-it 渲染 |
| Agent 服务端 | Node 22 + Express + LangGraph.js（@langchain/langgraph 0.4.x）+ ChatOpenAI |
| 持久化 | better-sqlite3（`data/app.db`，WAL）；对话工作区 `data/conversations/<对话id>/` |
| 附件解析 | fflate 解压 OOXML + 自研轻量 XML 提取（无重依赖） |
| 安装程序 | Inno Setup（用户级、内置 node.exe、中文向导）+ C# WinForms 控制台（系统 csc 编译） |

## 2. 架构与数据流

```
Word/Excel/PPT 任务窗格（Vue3）
  │  SSE /api/chat（thinking_delta / content_delta / message / interrupt / usage / done）
  ▼
Node 服务（LangGraph 状态图 START→agent→tools→agent…→END）
  │  Office 工具：interrupt() 暂停 → 任务窗格执行 → POST /api/chat/resume（Command resume）
  │  附件工具（side:"server"）：Node 内直执行，不中断
  ▼
SQLite 消息持久化（content/thinking/toolCalls/meta.attachments）
```

- **工具唯一来源**：`shared/tools-catalog.js`（服务端绑定 LLM、客户端映射执行器共用）
- **思考采集**：自定义 fetch 注入 OpenAI SDK，tee 原始 SSE 旁路解析（reasoning_content / reasoning / Responses API），展示与落库同源
- **旁加载**：持久写入 `HKCU\SOFTWARE\Microsoft\Office\16.0\Wef\Developer`（值名=manifest Id，值=manifest 路径），Office 启动时读取；功能区【开始】选项卡常驻"AI 助手"按钮

## 3. 功能清单（83 工具）

- **Word（27）**：信息/全文/分段读取、字数、光标、选区、插入文本/段落/分页/换行/符号/超链接/图片/表格、查找替换、删除、格式读写（含文档默认字体）、**全局样式库读取**、**样式应用（跨语言）**、**自定义样式创建/更新**、**run_code（AI 直接执行任意 Word.js 代码的兜底入口）**
- **Excel（26）**：工作簿/工作表管理、区域读写、公式、行列操作、格式化、排序、智能表格、查找、合并、图表、**run_code（Excel.js 全量兜底）**
- **PPT（25）**：信息、逐页文本、**形状清单**、新建/删除/移动页、**版式读取**、文本框/图片/表格/**几何形状/线条**、形状文字、**删除/移动/缩放单个形状、形状格式（填充/边框/重命名）、文字格式、层级调整、解散组合**、**文本框三件套：读取（含文字格式）/大小与位置调整/删除**、备注读写（按 API 集合特性检测）
- **通用（5）**：`ask_user` 表单、`think`、`get_office_context`、`attachment_list`、`attachment_read`（服务端直执行）
- **附件**：docx/xlsx/pptx/txt/md/csv/json（≤15MB×5/消息），读取内容与**有效格式**（样式链+主题字体+直接格式四级合并）
- **体验**：Markdown/思考折叠、工具卡片、智能跟随滚动（pinned 模型 + 回到最新按钮）、上下文额度、多模型切换
- **打包**：`npm run installer` → `installer/output/AI助手-Setup-1.0.0.exe`（36MB）

## 4. 关键决策记录

| 决策 | 理由 |
| --- | --- |
| LangGraph `interrupt()/resume` 客户端执行工具 | Office.js 只能在任务窗格运行；服务端图暂停等待 `POST /api/chat/resume` |
| 工具目录单文件共用 | 服务端绑定 LLM 与客户端 executor 映射同源，避免两处维护 |
| 证书只读取不安装（dev） | office-addin-dev-certs 交互安装会阻塞；安装交给 `npm run setup` / 控制台 |
| 附件工具 `side:"server"` | 文件在服务端，避免把文件内容传给任务窗格；工具节点自动分流 |
| 持久注册替代 debugging 临时文档 | debugging 工具的 start/stop 生命周期会反复注册/注销，且只开空白临时文档 |
| 数据目录可重定向（OFFICE_AI_DATA_DIR） | 安装版数据与程序分离，卸载/升级不丢数据 |

## 5. 修复史（根因 → 修复）

1. **Word 写入类工具全部失败**
   - `Range/Selection.insertParagraph/insertTable/insertBreak` 位置仅允许 Before/After（原传 Replace/End）
   - `select()` 枚举是 "Select"（原传 "Selected"）；超链接是 `hyperlink` 属性（无 insertHyperlink 方法）
   - `style` 属性按**本地化名**匹配（中文 Word 传 "Heading 1"/"Normal" 均 InvalidArgument）；内置样式必须用 `styleBuiltIn` 且枚举值**无空格**（"Heading1"）
   - Word.js 属性赋值是排队命令，**try/catch 包在赋值处无效**，错误在 `ctx.sync()` 才抛
   - 修复：`style-map.js`（28 内置样式映射）+ styleBuiltIn 主路径 + 逐次尝试 + 回读验证；错误包装带 code/debugInfo.errorLocation
2. **思考不持久化**：@langchain/openai 0.6.x 解析增量时丢弃 `reasoning_content` → 聚合消息也丢失。
   修复：原始 SSE 旁路捕获（单源），callModel 结束回填 `additional_kwargs`；测试覆盖（假 OpenAI SSE + 真实 ChatOpenAI）
3. **工具结果 JSON 混入正文增量**：messages 流模式会吐 ToolMessage chunk → handleChunk 仅处理 AI 类型
4. **旁加载"临时文档/AI 消失"**：任务窗格按文档隔离 + manifest 无功能区按钮 → VersionOverrides 三宿主 Home 按钮 + 持久注册脚本（`npm run register`）
5. **附件解析真实文档格式为空**：格式在样式链与主题字体 → docDefaults→basedOn 链→字符样式→直接格式四级合并 + theme1.xml 解析
6. **智能滚动失效**：80px 小阈值在流式渲染下被大增量误判 → pinned 意图模型（scroll 事件驱动，150px 阈值）
7. **闭标签正则形态错误**（docparse 重构过程中）：`<(?:[\w]+:)?\/X` ↔ `<\/(?:[\w]+:)?X`——注意 OOXML 闭标签前缀在 `/` 之后

## 7. 已知限制与后续方向

- 旧版二进制 `.doc/.xls/.ppt` 与 **PDF** 不支持（明确报错提示转换）；嵌套表格解析按首个 `</tbl>` 截断
- PPT 格式读取较浅（版式/字体/字号集合，无逐 run 对齐）；xlsx 不含填充色/边框（CellXfs 部分）
- 附件为纯文本级解析（非 OCR）；图片附件依赖模型视觉能力
- `run_code`（word/excel）与 PPT 形状级工具依赖真实 Office 运行时，离线自测未覆盖，需旁加载实测
- 待办候选：附件生成文件（如导出报告）入对话工作区、流式中断续传、Windows 服务方式常驻、多语言界面
- 环境备忘：Node 22.22.2 / 端口 3000 / 证书 `%USERPROFILE%\.office-addin-dev-certs` / 安装包数据目录 `%LOCALAPPDATA%\OfficeAI\data`

## 8. 增补记录（2026-10-29）：AI 能力全量开放（68 → 83 工具）

> 两条工作流：**Word/Excel `run_code` 万能兜底**（并行会话完成）与 **PPT 形状级操作全量开放**（本会话）。
> 背景诉求："给 AI 开放所有 PPT 权限"——AI 此前只能加/改文字、删整页，无法删除单个形状。
> 核查官方文档确认：Office.js 能力早已具备，缺口只在工具目录未定义、执行器未实现。
> 本项目无独立权限层，`tools-catalog.js` 即 AI 的权限边界。

### 8.3 Word/Excel `run_code`（并行会话，各 +1 工具）

- `word_run_code` / `excel_run_code`：AI 生成任意 Word.js/Excel.js 代码，在 `Word.run`/`Excel.run` 回调内执行，作为内置工具未覆盖能力的兜底入口
- 实现（两个执行器同构，`src/office/word.js` / `excel.js` 各 +51 行）：AsyncFunction 动态执行（作用域注入 Word/Excel 与 context，代码体支持 await/return）+ 超时保护（默认 30s，可调 1~120s，防死循环挂起）+ 收尾 `ctx.sync()` 确保队列中未提交写入落地 + 返回值 JSON 序列化（已 load 的代理对象经 toJSON 自动展开为普通数据）
- Excel 兜底覆盖场景（写入工具 description 引导模型）：冻结窗格、工作表/工作簿保护、条件格式、数据验证、命名区域、批注、自动筛选、分组与大纲、透视表、形状与图片、切片器、超链接、工作簿属性、跨表批量操作、自定义 XML 等
- 安全边界：代码仅在本机任务窗格（WebView2）内运行、只操作当前工作簿；约定读取前 `load()`+`sync()`、`return` JSON 可序列化对象；README 安全说明同步补充 `excel_run_code` 条目
- Excel 侧验证：`node --check` ✓；`toolsForHost('excel')` 绑定 31 工具（25 个内置 excel_* + 5 通用 + 1 兜底）✓；Excel 工具数 25 → 26（README 工具清单与总数 78 → 80 同步修正）

### 8.4 设计要点（PPT 形状工具）

- `pickTargets` 统一定位：id 优先、文本匹配兜底，返回 matchedCount 供结果提示；单目标工具用 `requireSingleSelector` 拒绝 shape_ids 防误操作
- `getSlideShapes` 一次 load 核心属性+文本；zOrder 二次 load 特性检测（旧 API 静默降级）
- 组合形状作为整体列出（type=group），子形状需先解组；图片/线条无 textFrame，format_text 明确报错
- 默认系统提示词破坏性操作清单加入"删除形状"（引导 ask_user 确认）；修正 `ppt_insert_textbox` 描述遗留的含糊注释

### 8.5 文本框三件套（第三轮，22 → 25）

| 工具 | 能力 |
| --- | --- |
| `ppt_get_textboxes` | 读取文本框（及其他带文字形状）：id/名称/位置尺寸/完整文字 + **文字格式详情**（字体/字号/加粗/斜体/下划线/颜色/对齐，嵌套 load 特性检测，旧 API 静默省略）；混合格式时对应项可能为 null |
| `ppt_adjust_textbox` | **大小与位置调整**：width/height（尺寸）、left/top（位置）至少一项、可任意组合；目标非文本框时照常执行并在结果中提示改用 ppt_move_shape |
| `ppt_delete_textbox` | 删除文本框：严格限定 type=textBox；按 id 删非文本框、或按文本只命中非文本框时，明确报错并引导改用 ppt_delete_shape；match_text 未命中但文本在非文本框形状中时给出精准提示 |

- 定位复用 `getSlideShapes`/`pickTargets`；删除沿用"剩余匹配数引导补删"模式（remainingTextboxes）
- `ppt_get_textboxes` 过滤规则：type=textBox 或 textFrame 文本非空（兼容占位符/带文字图形的类型枚举不确定性），条目保留实际 type
